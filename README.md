# 微信自动回复

忙的时候让它替你回微信，回得像你本人，不像机器人。

**两个人、两台设备，两条完全不同的路：**

| 你的情况 | 装什么 | 要电脑吗 |
|---|---|---|
| **只有安卓手机** | 装一个 APK | ❌ 不用 |
| **iPhone + Mac**（同一个微信号） | Mac 上双击一个文件 | ✅ Mac 要开着 |

> **完全不懂技术？** 别看这一页，直接看 **[新手指南.md](新手指南.md)** ——
> 那份是一步一步截图级别的说明，这一页是给要改代码的人看的。

## 它和 QQ 那种自动回复有什么区别

QQ 自动回复是「谁发消息都回同一句」。稍微好一点的做法是关键词匹配——
收到「在吗」回「在的」。问题是**它只能覆盖你想得到的情况**，
别人稍微换个说法就露馅。

真人回消息靠的是一套判断：我是谁、这事我怎么看、什么能答应什么不能。
所以这里把这套判断写清楚交给模型，它自己决定该说什么：

```
对方：明天下午有空不，一起吃个饭
你的自动回复：我看下日程，晚点回你

对方：那个东西弄得怎么样了
你的自动回复：在弄了，这两天给你结果

对方：帮我转账500
（不回复 —— 含敏感词，交给你本人处理）
```

这些话不是事先写好的，是现写的。你不用去猜别人会发什么。

## 但你不用自己写人设

「你是个什么样的人」是这套系统里最难写的东西。对着一个空框，
多数人会填「友好」「专业」这种词，生成出来必然是客服腔。

所以装完先问你十道题，八道是选择题：

```
  你平时打字是什么感觉？
    1. 简短随便，跟熟人聊天那种
    2. 客气一点，会用「您」
    3. 热情，愿意多聊两句，爱开玩笑
    4. 能少说就少说，一两个字就完事
  > 1

  有人约你见面、问你哪天有空——你希望怎么替你回？
    1. 先拖住，说要看一下日程
    2. 直接说最近排不开
    3. 先问清楚什么事
  > 1
```

答完直接给你看生成的结果，不满意可以重答：

```
  别人说「在吗」        → 在，怎么了
  别人约你吃饭          → 我看下日程，晚点回你
  别人问事情办得怎样    → 在弄了，这两天给你结果
  别人推销、拉群        → 这个我不太需要，谢谢
```

一次问答同时生成两套东西：**AI 模式的完整人设**，和**关键词模式的规则**。
选哪种模式都不用自己想文案。

## 安装

### 安卓（你朋友那台，不需要电脑）

**1. 拿 APK**

不用自己编译，GitHub 自动编好了：

[Actions 页面](../../actions) → 点最上面那条绿色 ✅ →
页面最下面 **Artifacts** → 下载 `微信自动回复-apk` → 解压得到 `.apk`

用微信发给他就行。

**2. 他手机上装**

点开安装。提示「禁止安装未知应用」就按提示允许一下。

**3. 打开后会自动进问答**

十道题，点一下就跳下一题。答完点「就用这套」。

**4. 授权 + 开开关**

App 里点「授予通知使用权（必须）」→ 在系统页面里找到「微信自动回复」打开
→ 回到 App 把最上面的大开关拨到开。

**5.（可选）想让回复更像真人**

在「怎么回」里选「让 AI 按你的说话方式现写」，然后二选一：

- **我自己注册一个（推荐）** —— 点「豆包」按钮，去
  [火山方舟](https://console.volcengine.com/ark) 建一个 API Key 粘进去。
  国内直连不用翻墙，新注册送额度。这条路谁也不依赖。
- **用别人给我的地址** —— 粘对方给的地址和口令，不用注册。
  代价：消息经过对方服务器，对方关机就不回了。

> 装完在「试一试」里输几句话看效果，不会真的发出去。
> AI 模式下这里会真的调一次接口，顺便就验证了 key 填对没有。

### macOS（你自己那台，iPhone 也跟着生效）

微信支持手机和 Mac 同时在线，收的是同一份消息。Mac 上自动回复，
对方看到的效果和你用 iPhone 回一模一样——**所以 iPhone 什么都不用装，
也不用越狱**。

```bash
git clone https://github.com/taotao-river/wechat-auto-reply.git
cd wechat-auto-reply
bash scripts/macos-setup.sh      # 会停下来问你那十道题
```

或者不想碰终端的话，双击仓库里的 **`安装到Mac.command`**（第一次要右键 →「打开」）。

装完还有两步：

1. **授权**：系统设置 → 隐私与安全性 → 辅助功能 → 勾选「终端」
2. **先干跑**：`./run-mac-bot.sh --dry-run`（只打印会回什么，不真发）

确认没问题后 `./run-mac-bot.sh` 正式开始。这个窗口得一直开着。

> 顺便：系统设置 → 电池 → 睡眠设成「永不」，否则合盖就停了。

**想用 AI 生成回复**（默认是关键词模式）：

```bash
export ARK_API_KEY=你的key       # 豆包的 key
python3 -m core.wizard           # 重答一遍，最后一题选「让 AI 现写」
python3 -m core.preview          # 打字试试，不会真的发出去
```

## 接哪家模型

```yaml
llm:
  provider: doubao        # 默认
```

| provider | 谁家 | key 从哪读 |
|---|---|---|
| `doubao` | 豆包（火山方舟） | `ARK_API_KEY` |
| `deepseek` | DeepSeek | `DEEPSEEK_API_KEY` |
| `qwen` | 通义千问 | `DASHSCOPE_API_KEY` |
| `zhipu` | 智谱 GLM | `ZHIPU_API_KEY` |
| `moonshot` | Moonshot | `MOONSHOT_API_KEY` |
| `anthropic` | Claude | `ANTHROPIC_API_KEY` |

**默认豆包**：这套东西要的是「聊天像真人」而不是解数学题，
它的中文口语是这几家里最自然的，国内直连、注册即用。
前五家都是 OpenAI 兼容接口，用标准库实现，装不装 `anthropic` 都能跑。

> 火山方舟的 `model` 比较特殊：模型 ID（`doubao-seed-1-6-251015`）
> 和推理接入点（`ep-` 开头）都能填，而模型 ID 带日期后缀会随版本变。
> 报「模型名不对」时去控制台复制一个填进去。

## 内置的几道保险

自动回复最大的风险不是不回，是**回错**。所以有几条不可关闭的规则：

**含转账、红包、验证码、银行卡、身份证、密码、借钱、汇款、付款码的消息，
一律不自动回。** 这个判断排在所有频率逻辑**之前**，哪怕你把冷却调成 0、
规则写成全匹配也拦得住。AI 模式下这类消息**压根不会离开你的设备**。

**模型只决定「说什么」，不决定「该不该说」。** AI 分支排在敏感词、黑名单、
群聊策略、频率限制之后。这几条不能靠在提示词里写一句「不要答应转账」了事——
那是概率性的，而回错一次的代价太高。

**三层限流。** 单会话冷却（默认 30 分钟）+ 单会话每日上限 + 全局每小时上限。
最后一层是保险丝，规则写错时最多刷 30 条。

**随机延迟 3–12 秒。** 秒回是最明显的机器特征，也最容易触发风控。

**默认加「（自动回复）」后缀。** 让对方知道在跟机器说话。可以关，但建议留着。

**失败一律不发。** 接口挂了、生成失败、读不到消息内容——所有异常路径都返回
「不回复」。AI 生成失败也**不会**偷偷退回关键词罐头话：你选了 AI 就说明
不想发那种话，冒出一句风格完全不同的句子比不回更糟。

**按账号隔离。** 限流的键是「账号 + 会话类型 + 归一化会话名」。
跑两个不同微信号时各算各的；同一个号在手机和电脑同时登录时，
两端填相同的 `account` 即可共享冷却并去重。见
[`docs/multi-account.md`](docs/multi-account.md)。

## 风险，说在前面

- **可能被封号。** 上面那些限流和延迟是为了把行为拉回「像人」的范围，
  但**不能保证不被判定**。建议一开始只对两三个熟人开，观察几天。
- **通知使用权和无障碍权限都非常大**，能读到手机上所有内容。
  只装你自己编译的、或者从本仓库 Actions 下载的版本。
- **AI 模式会把要回复的那条消息发给你选的接口。**
  敏感词消息和黑名单联系人的消息不会发出去（本机就拦了），
  上下文只在内存里最多留 8 轮、1 小时。介意的话就用关键词模式，
  那个模式一个字节都不往外发。
- 这些做法都是微信官方没有开放的，客观上违反用户协议，需要你自己判断。

## iOS 为什么是这个方案

**「装个 App 就自动回微信」在未越狱 iPhone 上不存在。**
iOS 沙盒不允许任何第三方 App 读取或发送别的 App 的消息——没有通知监听 API，
快捷指令拿不到微信消息，扩展也碰不到别的 App。这是设计如此。

真正能跑的有三条路，本仓库三条都实现了：

| 路线 | 要越狱吗 | 手机能正常用吗 | 实现 |
|---|---|---|---|
| **A. UI 自动化**（Appium + WDA） | 否，但要 Mac + 真机 | ❌ 微信要一直在前台 | [`ios/appium/`](ios/appium/) |
| **B. 注入插件**（Theos tweak） | 是 | ✅ | [`ios/tweak/`](ios/tweak/) |
| **C. macOS 代打** | 否 | ✅ 完全不占用手机 | [`macos/`](macos/) |

**路线 C 就是上面的 macOS 安装方法**，对绝大多数人是唯一合理的选择。
完整分析（含每种「想当然」的做法为什么行不通）：
[`docs/ios-feasibility.md`](docs/ios-feasibility.md)

## 项目结构

```
core/             规则引擎，纯逻辑，109 个单测
  engine.py         决策：安全检查 → 限流 → [AI | 规则] → 兜底
  wizard.py         开场问答：十道题 → 整套回复内容
  persona.py        人设、应对攻略、对话记忆、提示词拼装
  providers.py      能接哪些模型服务
  llm_openai.py     OpenAI 兼容接口生成（只用标准库）
  llm.py            Claude 生成
  preview.py        终端预览：不发消息就能调语气
  config.py         YAML 解析 + 校验（写错会明确报哪一项）
server/app.py     HTTP 服务，各端共用
android/          通知直接回复 + 无障碍兜底（Kotlin），76 个单测
  engine/           引擎、问答、AI 生成器的 Kotlin 移植，全内嵌
macos/            辅助功能 API 代打
ios/              见上面「iOS 为什么是这个方案」
docs/             安卓搭建、部署、iOS 可行性分析、多账号隔离
```

引擎写了两份（Python + Kotlin）是刻意的：手机上跑不了 Python 服务，
而要求普通用户装 Termux 敲命令不现实。两份的**判断顺序必须一致**，
两边的单测分别钉住了这一点。

跑测试：

```bash
python -m pytest -q                    # 109 个
cd android && ./gradlew testDebugUnitTest   # 76 个（CI 上也会跑）
```

## 还没验证的部分

诚实说明——以下只做到「编译通过、逻辑正确」，**没有在真机上跑过**：

- 安卓：微信通知能不能被正确拦到、`RemoteInput` 回复能不能真发出去、
  群消息通知格式在各个微信版本上的解析
- macOS：读微信窗口的辅助功能选择器（微信改版就可能失效）
- AI 接口：请求格式按 OpenAI 兼容规范写并对过文档，但没拿真 key 打过

前两项只能上真机试。第三项装完在「试一试」里输一句话就能验证。
